审阅日期：2026-09-16。对象：`drafts/dcc2027_submission_20260914/main.tex`。

遵照作者要求，未使用任何本地 skills。通过三个模型子任务分别检查方法、证据和审稿评价，由主任务核对关键原文及项目已有控制记录后综合。未运行新实验，未改论文，未联网检索新文献；关于新颖性的意见仅评估稿件自身的论证充分性。本报告不是实际会议评审，也不估计录用概率。

## 总体判断

**当前版本：倾向弱拒绝（Weak Reject），建议实质性修改后再投。** 主要原因是方法定义、主表实验配置与因果结论之间尚未对齐，并非已经证明方法无效。

论文有一个值得发表的观察：在具有 native merger 的 VLM 中，选择集合对取分位置敏感；对于所测文本密集任务，在合并前取分具有实证价值。三模型完整测试集、等 token 数比较、保留负面 GQA 结果，以及已有 matched-input 控制，都增加了可信度。实现保留完整原生单元与模型接口，也有工程价值。

但当前写作把一个“特征层级 + 排序阶段 + 实现契约”的有效设计，压缩成了“仅改变排序阶段”的故事；这超出了主表本身能支持的归因。RankBridge 另有实际样本量和显著性表述问题。应优先修证据链，而非继续润色措辞。

## 主要意见

### 1. 主表不能被解释为纯粹的 operator-order 效应【重大，已确认】

正文 186–203 行将 RBM 定义在 merger-input 上；245–246 行称主表 isolates the operator-order effect。可是项目现有 `reports/acmmm_final_controls.md:24` 明确：headline RBM 在 ViT layer-8 / deepstack[0]-input 取分，Post-L2 在主 merger 输出取分，存在 stage 与 feature space 的共同变化。

稿件 287–289 行已经给出更严格的 matched-input 控制，但它与主表并不是同一个实验：

| Qwen3-VL | 主表 RBM−Post-L2 | matched-input 控制 |
|---|---:|---:|
| TextVQA | +38.4 pp | +27.68 pp |
| DocVQA | +24.3 pp | +4.59 pp |
| OCRBench | +363 点 | +235 点 |
| GQA | −2.8 pp | −5.64 pp |

DocVQA 尤其说明：主表收益不能全部归于“提前排序”。这不推翻 pre-merger 选择的正向效果，但会改变贡献解释。也不能直接把两列差额全部解释为 feature depth 的独立因果贡献，因为已有记录还涉及 deepstack 路径的配置差别。

**最小修复：** 明确区分实际 RBM 的 early-feature tap 与匹配主 merger 输入的机制控制；逐模型列出 tap、归一化位置、stream 和顺序处理。把 matched-input 控制提升为主论证证据，将主表称为最终方法性能比较。Qwen2.5 的 ordering confound 已在 389–390 行承认，摘要与结论的跨模型归因应同步收窄。

### 2. TextVQA 的“显著提升”尚缺匹配官方评分的检验证据【重大，已确认口径问题】

正文 293–295、392–393 行将 RankBridge 的 +3.2 pp 视为显著，并给出 z=2.11。`experiments/rankbridge_gate.md:50–52` 的来源是二值不一致对 b10=9、b01=2，而官方 TextVQA 指标为软 VQA accuracy。

这 11 个二值不一致对的未校正渐近统计量确为 7/√11≈2.11，但双侧 exact McNemar p=0.06543。这个计算并不是对官方软分数差的重新检验；它说明稿件所给 z 值不能充分证明目标指标的显著提升。若把四个 benchmark 作为同一探索性检验族，还需明确多重比较策略；不能直接沿用主表九项比较的 Holm 声明。

**最小修复：** 用逐样本官方软分数差进行配对 bootstrap 或合理的置换检验，给出差值 CI、p 值、检验族和预先指定的主终点。完成前改写为“观察到 +3.2 pp 的提升”。此处不能反过来断言软分数检验必然不显著。

### 3. OCRBench 的 n=200 是计划量，实际分析为 n=181【重要，已确认】

正文 211、239、302–304 行统一写 n=200。已有 gate 记录 53 行明确：OCRBench 为 181/181，有 19 个共同加载跳过样本；表内 .5801/.4586/.4641 对应 105/181、83/181、84/181 的舍入结果。

共同剔除保留了各方法之间的配对关系，不等于没有样本筛选影响。

**最小修复：** 每行列出计划 n 与有效 n，说明排除原因、排除是否与方法无关，以及所有方法是否使用完全相同 ID。补充开发集与锁定集的 ID 不重叠证据和抽样方式。已有开发 gate 信息可以补写，不应把正文信息不足直接定性为数据泄漏。

### 4. 机制控制的证明范围需要收窄【重要】

151–171 行给出的集合相等与单调映射条件是合理形式化，但本身没有解释“什么架构或任务会受益”。355–358 行 ranking-swap 恢复同一集合、同一输出，是排除被保留单元计算差异的有效实现检查，不能单独证明 L2 捕获了因果相关的文字证据。

349–353 行的 Sobel 能量也不是文字特异性指标，边框、纹理与物体轮廓同样会产生高频边缘。当前相关性支持“高边缘能量单元受影响”，对“文本笔画被系统压低”的解释还需更直接证据。

**最小修复：** 将 swap 明确定位为路径等价性控制；区分 rank disagreement、边缘相关性和任务分数三层证据。若进一步做实验，优先用文字框覆盖、文字/非文字对照或相关区域替换，而不是再增加相同类型的可视化。

### 5. Post-L2 是诊断基线，尚不足以支撑广义选择器优势【重要】

主表的匹配 L2 对照适合检验机制，但不能覆盖相关工作中不同选择策略。稿件自身 311–314 行显示 FastV 在 TextVQA、DocVQA、GQA probe 上强于纯 RBM；320–322 行也承认各方法占优任务不同。因此“保留原生单元且使用 pre-merger 信号”是当前较稳健的贡献，而不是通用最好选择器。

**最小修复：** 展示已经完成的完整 FastV 结果及各方法对应的 uncompressed 基线，明确 HF/vLLM 跨后端比较的验证限度。若追加实验，优先选择同模型、同有效样本、同预算的代表性强方法，并比较准确率与实际成本的折中。不要用更大的样本量替代缺失的公平基线。

### 6. 效率与 rate–distortion 的定义需要可复现边界【重要】

173–182 行的 R=k/N 是 token 保留比例，D=1−S(R)/S(1) 是相对任务分数损失，可作为任务压缩工作点，但并不是比特率或编码意义上的失真。FastV 在前 K 层仍保留全部候选（207–213 行），因此相同最终 R 不代表相同总算力。

382–387 行给出吞吐、延迟和五次重复，但未充分说明输入像素/token 分布、输出长度、并发、batch、预热、计时范围，以及吞吐与延迟是否来自同一负载。1.68× 吞吐提升支持压缩的整体收益；RBM 与 Post-L2 吞吐接近，并未显示明显的额外前置选择加速。

**最小修复：** 增加简短测量协议和阶段耗时；区分最终 token rate、LLM 各层 token 工作量与墙钟成本。无需为了术语而强行构造 codec，但应明确采用的是任务层面的 token-budget distortion。

## 次要意见及待核查项

- 摘要 58 行的 235–432 OCRBench 点混合了 matched-input 控制下界与主表上界；主表三个差值为 298、363、432。应将主结果与机制控制分开报告。
- Table 2 的 `RB−FastV` 与 RBM 缩写容易混淆，建议写全 `RankBridge−FastV`。
- Fig.1 使用 K=round(ρN)，正文用 κ 表示保留率、ρ 表示 RankBridge 混合比例，符号应统一。
- Table 1 的三位小数与一位百分点差值存在显示精度上的差异，例如 .605−.222=38.3 pp 而表列 +38.4；这可能只是原始精度舍入，应加一句“差值按未舍入分数计算”，不能据此断言算术错误。
- 249 行称 12.5% 时 gap widens，不宜笼统推广到全部文本任务；请按任务核对，并明确相对 gap 还是绝对分数差。
- Fig.3 使用单独 n=200 diagnostic subset。图源脚本的若干工作点与 Table 2 不同，这本身可能来自不同样本或指标，不能据此认定错误；应给出对应 ID、计分口径与原始记录，确认 caption 的 official task score 可追溯。
- “多数 post-merger 选择器隐含假定排名保持”过强：方法选择在后层打分，不必然作此假设。更稳健的引入是“后层分数未必保留早层有用线索，因此比较选择域的影响”。

## 建议修改顺序

1. 先统一方法定义、特征 tap、主表与 matched-input 控制，重写摘要和主贡献中的因果措辞。
2. 用已有逐样本记录修正样本量和统计口径，核实所有图表的样本、指标和来源。
3. 把已有完整强基线结果与效率协议写入正文或可引用补充材料。
4. 再决定是否投入新的机制对照或强基线实验；本轮没有启动训练、GPU 实验或投稿。

最值得保留的论点是：**在所测具有 native merger 的模型与文本密集任务上，pre-merger 信号能改善选择；其贡献需要与特征深度、模型实现和任务类型分别界定。** 现有 matched-input 结果为这个论点提供了实质证据，修正归因可以提高论文可信度，而不是削弱它。
