# 独立模型审稿：贡献、定位与接受判据

审阅对象：`drafts/dcc2027_submission_20260914/main.tex`，2026-09-16 当前版本。主体意见依据稿件中呈现的论证与结果；末尾附交叉审阅指出后、由本审阅者阅读两个必要实验摘要所确认的事实。未使用本地 skills、未联网核验文献、未运行实验、未检查底层实现或独立复核逐样本数据。正文问题的行号对应当前 TeX 源文件。以下模拟严格压缩领域审稿，非真实 DCC 审稿结果或录用预测。

## 总体判断

**内部模拟建议：Weak Reject（弱拒），接近可通过有针对性修订改善的边界。** 对稿件内部论证问题的判断把握较高；对外部新颖性与实际会议竞争力不作已核实判断。

本文有一个清楚且值得报告的经验发现：在包含原生空间合并器的 VLM 中，相同预算下，合并前的块范数与合并后的 token 范数会选择很不相同的视觉区域，前者对若干文本密集任务明显更有效。三模型、完整测试集、九个文本任务组合及 GQA 反例，使该发现比单模型的小样本现象更有说服力。保持模型权重与接口不变的实现也有实际价值。

当前版本把这一发现提升为一般性的“operator-order failure”，但最强因果证据主要支持 **Qwen3-VL 上两个范数评分位置的比较**。引言对于现有选择器的隐含假设、数学贡献的新知识含量、相对强基线的实用价值、文本笔画机制的特异性，尚未被相应强度的证据支撑。对严格审稿人而言，这些是决定性问题，不只是英文表达问题。

## 我认可的优点

1. **问题隔离有价值。** 固定完整 native units 和每图预算，可以避免将 token 数量差异误当成方法优势（151–171、186–203、254–256 行）。在 Qwen3-VL 上，ranking-swap 与 byte-identical 验证进一步收窄了差异来源（355–358 行）。
2. **主结果规模扎实。** 三个模型的九个文本密集完整集比较，效果差距大，并进行了配对统计检验（225–239、247–279 行）。如果实现和评测可信，这足以支持一个稳定的工程发现。
3. **失败边界写得诚实。** GQA 反转、RankBridge 在 OCRBench 上未达到预定门槛、另外三个混合增益不显著，以及跨模型归因限制，均有正面披露（285–298、389–395 行）。
4. **方案简单、可部署。** 不训练、不增参数、沿用原始 merger，降低复现与迁移成本。文中也说明不能节省评分 tap 以前的 ViT 工作（186–203、382–387 行）。
5. **结构有主线。** 从选择位置、预算匹配，到工作负载反转和混合先验，整体问题意识明确。本文不是毫无根据地宣传普适压缩器。

## 主要问题

### M1. 核心叙述把“范数排序改变”扩大为“现有选择器的错误假设”

**位置：50–60、74–80、97–106、245–246、343–365 行。**

摘要与引言说多数选择器在原生 merger 之后评分，并因此隐含假定合并前后显著性保持。这两个命题并不等价：后置、问题条件化的评分器完全可以利用合并后空间中的语义或 attention，而不要求它保留合并前 L2 顺序。当前实验明确限制于 query-blind L2 的主比较，不能据此认定其他选择器存在相同的设计失误。

“hiding answer-bearing regions”还包含超出排序数据的推断。merger 改变向量范数，并不等于 answer-bearing information 已在表示中丢失。ranking-swap 恢复准确率，恰好说明合并后的保留表示仍可有效使用；已证实的失败发生在所选 post-L2 排序准则，而不是证明 merger 本身不可逆地抹除了文本证据。

**修订要求：** 将最强结论限定为“native merger may invalidate feature magnitude as a proxy for selection saliency”，明确“证据在选择时被丢弃”与“merger 表示本身丢失证据”的区别。若保留对多数选择器的概括，需要展示相关方法确实依赖这个假设，以及至少一个强评分器受到同类失效影响的直接证据。

### M2. 数学形式化目前主要是定义，尚不足以独立支撑一个理论贡献

**位置：103–106、149–171、186–203 行。**

对于逐块独立的 merger，固定集合后的 gather 与 merger 可以交换。当前所谓“不交换”来自前后两个评分函数产生了不同集合。161–163 行“集合相同当且仅当选择一致”基本是定义展开，严格单调变换保序也是直接性质。它是有用的解释框架，但没有给出关于真实 merger 何时保序、何时失序、失序如何影响任务损失的新预测。

另外，190–192 行的两个评分公式并非简单地对同维表示重复同一计算：一个是四个 patch 范数的平均，另一个是 merger 输出范数。因此，更准确地说，实验替换了评分所在的表示及该表示上的范数聚合方式。它很好地控制了预算与保留表示，但不应把所有差异都表述为一对固定算子的单纯换序。

**修订要求：** 把本节定位为分析框架而非强理论结果，并明确区分“固定索引下算子可交换”与“表示依赖的自适应选择不可交换”。如欲维持理论贡献地位，需要可检验的条件、预测或界，而非只给集合相等定义。范数聚合方式的最小对照，也有助于排除 block scoring 定义本身驱动结论。

### M3. 对压缩方法价值的最强证据仍主要来自击败 Post-L2

**位置：254–279、291–322、382–395 行。**

Post-L2 是合理的因果控制，但它在部分任务上大幅坍塌；击败它足以证明“不要这样选”，尚不足以证明 RBM 是有竞争力的压缩选择。在 Qwen3-VL 完整集上，RBM 从未压缩的 .844/.956 降至 TextVQA .605、DocVQA .481。与此同时，200 样本表中 FastV 的 TextVQA .7633、DocVQA .5863 明显高于 RBM .5967/.4239。这意味着 RBM 自身在部分目标文本任务上的实际取舍仍然不理想。

全文诚实说明 OCRBench 是 RBM 较强的区域，但目前表格没有把这一优势放进统一的强基线、质量与代价对照。vLLM 与 eager 的差异也使目前结果不能证明 RBM 相比 FastV 的端到端速度优势。

**修订要求：** 保留 Post-L2 为机制控制，另设同模型、同预算、清楚报告计算阶段的竞争性比较。最低限度应把已提及的完整 OCRBench/FastV 结果正式表列，给出完整协议与数值；同时加入简单但不失真的随机/均匀选择基线，帮助判定 post-L2 的退化程度。若无法补广泛竞争实验，应将文章定位为特定范数信号的失效分析和修复，而降低通用“新压缩器”的强调。

### M4. 相关工作覆盖面广，差异论证不足

**位置：110–145 行，尤其 128–136、141–145 行。**

当前相关工作罗列了大量方法类别，其中明确提及“move reduction earlier”。但文章没有选出最接近的两三个工作，逐一解释它们是否已经在 native merger 前进行选择、是否保留完整 native units、其 score 与接口约束有什么区别。末段“RBM isolates the native-merger boundary”是作者主张，并未完成与最近邻工作的区分。

我不能在未核查这些论文时断言 RBM 没有创新；可以确定的是，**稿件本身尚未使创新边界可评估**。51 篇引用的数量不能替代两三篇最近邻的技术比较。

**修订要求：** 压缩广泛名单，为最近邻比较让出篇幅。用少量明确维度说明既有方法与 RBM 的区别，并区分“工程选择本身的新颖性”与“首次受控揭示 merger 对选取信号的影响”这两种可能贡献。

### M5. Sobel 结果支持边缘偏好，尚不特异地识别文本笔画或答案证据

**位置：52–59、349–353、363–365 行。**

Sobel edge energy 对文本轮廓、非文本纹理和其他高频结构都会响应。相关系数和 RBM-only 单元边缘能量说明两类排序在边缘上存在系统性差异，但不足以直接将这些单元称为“text-stroke-rich”，更不足以证明它们是回答问题所需区域。DocVQA 的任务性质使这个解释合理，却不是区域级验证的替代。

ranking-swap 控制证明差异来自选中集合，而不能证明集合为何对 OCR 有益。因此“三个诊断解释机制”的措辞应区分：排序变化是直接证据；文本笔画 demotion 是目前由边缘代理支撑的解释。

**修订要求：** 明确 Sobel 是 proxy，并披露计算和归一化方法、样本数、排名方向。更强机制需要文本框/字符掩码覆盖率、非文本边缘对照，或与答案相关区域的保留率。若不补实验，将摘要与图注的因果措辞收窄即可避免过度解释。

### M6. 影响主结论的条件与复现细节披露过晚、过简

**位置：210–213、225–239、285–289、293–298、320–321、382–394 行。**

这里存在几个会直接改变证据强度的未解问题：

- Qwen2.5-VL 的“ordering confound”和 InternVL3 的“bounded swap”仅在结尾各用数词带过，读者无法判断跨模型主表在多大程度上隔离了 operator order。
- “matched at the merger input”的完整集控制没有给出具体比较对象或操作。DocVQA 增益由主表 +24.3pp 变为 +4.59pp，这一变化尤其需要解释；目前无法判断多少主结果差距属于最纯净的排名效果。
- RankBridge 的 development gate 与四个 locked n=200 探针之间的划分、重叠、抽样方案及调参目标没有说明。TextVQA 单独的 z=2.11 也不足以说明该混合模块的完整统计程序。
- 8/8 和 16/16 一致是有用的 smoke test，不能定量限定完整跨后端比较误差；两个后端的样本级分歧与是否会影响方法排序未报告。
- 速度数字没有说明数据集、输入像素/视觉 token 分布、输出 token 长度、batch/concurrency、warm-up、延迟统计口径。吞吐和延迟可以来自不同测量方式，但读者目前无法复现并理解它们的关系。

**修订要求：** 在协议中优先交代会影响因果归因的条件，而不是将其压缩到 limitations。无需堆积日志，应以清楚的比较定义、数据划分与测量口径解决问题。

## DCC 定位评价

**位置：173–182、324–335、382–406 行。**

把视觉 token 预算称为 rate、把归一化任务分数损失称为 task distortion，是能够理解的任务导向压缩视角。本文不必为了显得像压缩论文而强行提供熵编码或码流；题材本身也不应仅因没有 bit rate 被否定。

但当前 R=k/N 是表示保留率，既非实际传输 bits，也不直接等于端到端推理代价。特别是 FastV 在前三个 LLM 层保留所有 tokens，因此相同最终 R 不保证相同计算成本。D(R)=1−S(R)/S(1) 是操作性效用损失，并不直接度量“信息存活量”。若称之为 rate–distortion design，最好将其限制为模型内、任务内的经验操作点，同时提供质量—实际资源代价关系。否则公式容易被视为给一般 pruning 曲线换名，而压缩设计的独特洞见仍不够突出。

## 哪些改动会实质影响我的推荐

**最优先、无需新实验也能改善：** 收窄“most selectors / implicit assumption / answer-bearing regions”等概括；明确定义 matched control 和 ordering confound；给出最近邻技术差异、development/evaluation 划分与测量协议；将数学节定位为框架。这可以显著改善可信度与可评估性。

**可能改变录用倾向的核心证据：** 在清楚控制的环境中，展示 RBM 或其预合并先验相对有竞争力的选择器具有可解释的质量—代价优势；或用更直接的文本证据保留控制，建立足够强的机制发现，使文章以“受控失效分析”而非“普适压缩算法”成立。

我不会要求作者同时铺满所有方向。最有效的是明确选择文章要成立的路径：**窄而扎实的 merger/范数信号失效研究**，或 **具备强基线竞争力的新压缩方法**。当前版本在前一路径上证据较强，但多处叙述仍借用了后一路径的影响力。

## 交叉审阅后确认：应优先修正的三项事实

以下不是凭论文缺少说明而推测的问题。协调审阅提供线索后，我读取了 `reports/acmmm_final_controls.md` 的 21–43 行，以及 `experiments/rankbridge_gate.md` 的 1–58 行，并确认文稿与项目实验摘要之间存在这些差异。它们使 M1、M2、M6 的担忧更加具体。

1. **主表并非只改变同一 merger 两侧的评分位置。** `reports/acmmm_final_controls.md:24` 明示 headline RBM 在 ViT layer-8/deepstack[0]-input tap 评分，Post 在 main-merger 输出评分，含 stage 与 feature-space 两重混杂；真正 pre-final/post 控制使用主 merger 自身输入，且两侧保持 deepstack mergers 完整。该报告 38–40 行给出 TextVQA +27.68pp、DocVQA +4.59pp、OCRBench +235 分。故稿件 245–246 行“isolates the operator-order effect”、82–85 行“one intervention”以及抽象统一公式与 headline 实现的关系必须重写。仍然存在真实的纯位置收益，但不可将主表 +24.3pp 的 DocVQA 收益全部归因于同一个 merger 的输入/输出顺序。应明确区分主方法的早层评分和用于归因的 pre-final 控制。
2. **RankBridge 的 OCRBench 实际有效样本数是 181。** `experiments/rankbridge_gate.md:53` 明示 19 个 shared load skips。稿件 302–304 行将整表称为 n=200，且未披露排除，容易让人认为这是 200 个样本的完整评估；表中 .5801/.4586/.4641 也与 105/181、83/181、84/181 相符。应注明 attempted=200、evaluated=181、剔除原因与各方法配对规则，并说明是否有其他图表沿用相同过滤集合。
3. **TextVQA“显著”需要重新核验实际指标与检验。** `experiments/rankbridge_gate.md:50–52` 将 z=2.11 与二值不一致对 b10=9、b01=2 相联系；相应无连续性修正统计量为 (9−2)/sqrt(11)=2.11。对这 11 个不一致对进行双侧 exact McNemar，p=2×(1+11+55)/2^11≈0.06543，未达 .05。更关键的是，论文提升指标是 soft VQA accuracy，不能仅凭这组二值不一致计数确认其均值差显著。应读取逐样本 soft-score 差值执行相应配对检验，再决定 294–295 与 392–393 行的显著性表述。这个发现不证明 soft-score 增益一定不显著，只说明当前呈现的 z 不能充分支撑该断言。

这三项应先于新增大型实验解决；它们涉及报告准确性与主结论归因，而非写作偏好。
