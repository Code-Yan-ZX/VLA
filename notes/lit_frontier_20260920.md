# 2025–2026 视觉 Token 压缩前沿：可核验论文与边界

> 2026-09-20 检索。仅把 CVF Open Access、ICLR Proceedings、ACL Anthology 的正式论文列为「已发表」。范围是 VLM/MLLM 推理视觉 token；以下优缺点中，**优点为论文主张，局限为从机制及其报告范围推导的研究判断**，不代表跨论文同硬件复现。本文是针对重点痛点的核验清单，不声称穷尽全部论文。

| 痛点 / 工作（正式来源） | 做法与具体解决点 | 长处（作者报告） | 局限 / 仍需检验 |
|---|---|---|---|
| 早剪缺少问题语义：[QuietPrune, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Gao_QuietPrune_Query-Guided_Early_Token_Pruning_for_Vision-Language_Models_CVPR_2026_paper.html) | 逆 projector adapter 把 query 映射为 ViT 内 Q-CLS；按 2×2 邻近组剪并聚合冗余 token，兼顾原生视觉合并结构。 | 在 Qwen3-VL/InternVL3 上，相对所比晚剪方法，报告最高 19.0% prefill 延迟降低及 4.2% 准确率提升。 | 已占据「早期 query-aware + 原生 2×2 兼容」空间；adapter、组粒度和模型耦合需单列成本，细小字符能否在组内保留仍需验证。 |
| 文档图像背景大、证据稀：[DocPrune, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Choi_DocPrune_Efficient_Document_Question_Answering_via_Background_Question_and_Comprehension-aware_CVPR_2026_paper.html) | 先删背景、再按问题相关性、后按模型理解程度选层继续剪。 | M3DocRAG 上作者报告 encoder/decoder throughput 分别 3.0×/3.3×，F1 +1.0；明确覆盖文档 QA。 | 「OCR/文档压缩无人做」已错误；主要证据是 M3DocRAG，需跨 OCRBench/DocVQA/ChartQA、超细字和多页引用做同预算核验。吞吐指标不可直接当作整套服务吞吐。 |
| 信息何时消失：[When Token Pruning is Worse than Random, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_When_Token_Pruning_is_Worse_than_Random_Understanding_Visual_Token_CVPR_2026_paper.html) | 用删 token 引起的输出概率变化测信息，发现深层信息趋同的 horizon，且 OCR 的 horizon 较深。 | 解释部分晚层复杂选择器不如随机，提供 layer × task 控制基线；DivPrune+随机在 Qwen2.5-VL-7B 剪半 token 时维持 96.9% 表现。 | 深层后剪省不了前端已花的编码/prefill；horizon 依模型和任务移动，不能写成统一固定层数。 |
| 单 token 分数忽略集合覆盖：[MMTok, ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/4f8745c0ca5c951a92844ad7668cfca5-Abstract-Conference.html) | 把保留集合定义为同时覆盖文本 token 和原始视觉 token 的最大覆盖问题。 | 体现相关性与多样性互补；作者报告 LLaVA-NeXT-13B 在 POPE 1.87× 加速、保留 98.7% 性能。 | 覆盖代理仍不等于答案因果贡献；集合优化和文本对齐开销在大规模高分辨率输入上须算进总延迟。 |
| 文本相关性会丢背景：[CrisPrune, Findings ACL 2026](https://aclanthology.org/2026.findings-acl.663/) | 内在视觉显著性、显式/隐式文本相关性与 DPP 多样性联合。 | 作者报告 LLaVA-NeXT 剪 94.4% token，FLOPs 减 13×，保留 97% 原性能。 | 多信号方法已密集；DPP 的计算成本和对模糊 query、文字/图表关键细节的条件表现需核验。 |
| 固定剪枝配置不在 Pareto 前沿：[VisPCO, ACL 2026](https://aclanthology.org/2026.acl-long.420/) | 将层与预算配置写成受预算约束的 Pareto 优化，用梯度搜索。 | 8 个视觉基准上作者报告接近 grid-search 经验 Pareto 前沿，显示多步渐进剪优于单层。 | 搜索依赖代理任务/模型；线上请求形状、批处理和迁移后是否仍在 Pareto 前沿需再测。 |
| attention 代理依赖不可得的权重：[ApET, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Ma_ApET_Approximation-Error_Guided_Token_Compression_for_Efficient_VLMs_CVPR_2026_paper.html) | 用少量 basis 线性重建视觉 token，按近似误差筛选，绕开 attention 分数。 | 与 FlashAttention 兼容；作者报告图像/视频预算各减 88.9%/87.5%，表现保留 95.2%/100.4%。 | 重建误差是表征代理，未必保护稀有数字/极小字；兼容高效 kernel 不自动证明连续批处理的 goodput。 |
| 复杂输入需学习压缩策略：[EvoComp, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Song_EvoComp_Learning_Visual_Token_Compression_for_Multimodal_Large_Language_Models_CVPR_2026_paper.html) | 以演化搜索构造近似输出损失最小的子集标签，训练轻量 encoder-only 压缩器结合图文语境。 | 3× 压缩时作者报告保留 99.3% 准确率，移动设备至多 1.6× 加速。 | 训练/搜索和设备迁移成本高于纯推理剪枝；跨模型新域及尾部稀有证据仍需测试。 |
| 高分辨率固定预算不适合每个问题：[AdaptVision, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Lin_AdaptVision_Efficient_Vision-Language_Models_via_Adaptive_Visual_Acquisition_CVPR_2026_paper.html) | 先用低分辨率压缩视觉输入，需要时用 bbox crop 主动取得局部高清 token，并以 RL 学习决策。 | 让模型按样本申请额外视觉信息，论文报告相对高效 VLM 方法更少 token、更好 VQA。 | 主动裁切增加回合/工具延迟；首轮未定位到微小证据时可能无法申请正确区域；训练和服务架构更复杂。 |
| 仅压 LLM 忽视视频编码成本：[EarlyTom, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_EarlyTom_Early_Token_Compression_Completes_Fast_Video_Understanding_CVPR_2026_paper.html) | 视频视觉编码器内早压缩，特别指出 ViT 编码是 TTFT 主要组成。 | LLaVA-OneVision-7B、单 A100 上作者报告 TTFT 至多 2.65× 改善，FLOPs 至多降 61%，并报告 throughput 改善。 | 视频特有的帧间冗余和单卡设置不能直接外推单图 OCR；仍需多并发及不同 encoder 的系统复现。 |
| 流视频 token 无界增长：[StreamingTOM, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Chen_StreamingTOM_Streaming_Token_Compression_for_Efficient_Video_Understanding_CVPR_2026_paper.html) | 每帧固定预算的因果时序选择 + 4-bit 在线量化记忆按需检索，覆盖 prefill 与 KV。 | 作者报告 KV 压缩 15.7×，相对 LiveVLM 峰值内存 1.2× 更低、TTFT 2× 更快。 | 固定每帧预算遇短时稀有事件可能不足；量化和检索开销、长时证据完整性需单独测。 |
| 视频编码与 LLM prefill 双瓶颈：[STC, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_Accelerating_Streaming_Video_Large_Language_Models_via_Hierarchical_Token_Compression_CVPR_2026_paper.html) | 跨相近帧缓存 ViT 特征，随后在 LLM 前做时空相关性剪枝。 | 四个 streaming VideoLLM 的实验；ReKV 上至多保留 99% 准确率，ViT 编码/prefill 延迟分别降 24.5%/45.3%。 | 缓存命中依赖视频相似性；需细查快速变化、场景切换和整体流水线收益。 |
| 视频超低预算的时空冗余：[Unified Spatiotemporal, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Du_Unified_Spatiotemporal_Token_Compression_for_Video-LLMs_at_Ultra-Low_Retention_CVPR_2026_paper.html) | 时空联合压缩，LLM 内再用文本相关性合并。 | 作者报告只留约 2% 视觉 token 时维持 90.1% 基线性能，FLOPs 约 2.6%，并报告端到端延迟下降。 | 平均指标仍容许个别关键帧失败；视频方法不直接证明单图细粒度 OCR 安全。 |
| decoder KV 历史冗余：[MuKV, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Xiao_MuKV_Multi-Grained_KV_Cache_Compression_for_Long_Streaming_Video_Question-Answering_CVPR_2026_paper.html) | patch/frame/segment 多粒度 KV 压缩，在线分层检索。 | 作者报告长流视频 QA 精度、内存、在线效率协同改善。 | 主要作用于历史 KV 与在线检索；不等同减少首次视觉编码，索引/检索费用需算。 |

## 必须修正的旧 gap

1. `notes/new-papers-and-qwen35vl.md` 的「没有 image/OCR VLM 的 vLLM/SGLang 集成论文」是**窄定义**；不能由它推得「没有部署加速或 TTFT 论文」。[DocPrune](https://openaccess.thecvf.com/content/CVPR2026/html/Choi_DocPrune_Efficient_Document_Question_Answering_via_Background_Question_and_Comprehension-aware_CVPR_2026_paper.html) 报告文档吞吐；[EarlyTom](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_EarlyTom_Early_Token_Compression_Completes_Fast_Video_Understanding_CVPR_2026_paper.html) 与 [StreamingTOM](https://openaccess.thecvf.com/content/CVPR2026/html/Chen_StreamingTOM_Streaming_Token_Compression_for_Efficient_Video_Understanding_CVPR_2026_paper.html) 报告 TTFT；[ApET](https://openaccess.thecvf.com/content/CVPR2026/html/Ma_ApET_Approximation-Error_Guided_Token_Compression_for_Efficient_VLMs_CVPR_2026_paper.html) 明确处理 FlashAttention 兼容。
2. 「OCR/文档专门化仍无人涉及」已被 [DocPrune](https://openaccess.thecvf.com/content/CVPR2026/html/Choi_DocPrune_Efficient_Document_Question_Answering_via_Background_Question_and_Comprehension-aware_CVPR_2026_paper.html) 推翻；[information horizon](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_When_Token_Pruning_is_Worse_than_Random_Understanding_Visual_Token_CVPR_2026_paper.html) 还说明 OCR 与普通 VQA 的可剪层深度不同。
3. 「query-aware 早剪」已被 [QuietPrune](https://openaccess.thecvf.com/content/CVPR2026/html/Gao_QuietPrune_Query-Guided_Early_Token_Pruning_for_Vision-Language_Models_CVPR_2026_paper.html) 直接占据；「视觉/文本相关性 + 覆盖」也已有 [MMTok](https://proceedings.iclr.cc/paper_files/paper/2026/hash/4f8745c0ca5c951a92844ad7668cfca5-Abstract-Conference.html) 与 [CrisPrune](https://aclanthology.org/2026.findings-acl.663/)。

## 经本轮核验后仍可提出的具体问题

- **联合评估的缺口**：本表文档专用论文主要在 M3DocRAG 给出 F1 和组件吞吐；视频论文在各自视频基准报告 TTFT/内存；在**同模型、同输入、同保留预算、同硬件**下，同时覆盖 OCRBench/DocVQA/ChartQA 的细粒度正确率、整条服务链 p95 TTFT、goodput 和峰值显存，仍是值得设计的实验。这里仅说本轮所核验论文未形成统一证据，不声称全领域无人做。[DocPrune](https://openaccess.thecvf.com/content/CVPR2026/html/Choi_DocPrune_Efficient_Document_Question_Answering_via_Background_Question_and_Comprehension-aware_CVPR_2026_paper.html)、[EarlyTom](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_EarlyTom_Early_Token_Compression_Completes_Fast_Video_Understanding_CVPR_2026_paper.html)、[ACL 2026 综述](https://aclanthology.org/2026.acl-long.328/)。
- **证据保护的条件化边界**：OCR horizon 更深；文档方法已处理背景和问题；早期 query-guided 已出现。可继续问：在**极小文字、跨页表格引用、稀有数字、含糊 query**时，哪些 token 删除错误不可恢复，如何给出风险条件预算，而非再发明无条件 top-k。[信息 horizon](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_When_Token_Pruning_is_Worse_than_Random_Understanding_Visual_Token_CVPR_2026_paper.html)、[DocPrune](https://openaccess.thecvf.com/content/CVPR2026/html/Choi_DocPrune_Efficient_Document_Question_Answering_via_Background_Question_and_Comprehension-aware_CVPR_2026_paper.html)、[CrisPrune](https://aclanthology.org/2026.findings-acl.663/)。
- **硬件与配置泛化**：现有方法已优化 FlashAttention 兼容和离线 Pareto 配置；下一步应检验压缩器开销、动态形状、连续批处理、不同并发和不同 encoder 下的实际 Pareto 前沿与尾延迟。[ApET](https://openaccess.thecvf.com/content/CVPR2026/html/Ma_ApET_Approximation-Error_Guided_Token_Compression_for_Efficient_VLMs_CVPR_2026_paper.html)、[VisPCO](https://aclanthology.org/2026.acl-long.420/)、[ACL 2026 综述](https://aclanthology.org/2026.acl-long.328/)。

**阅读约束**：单篇的「至多」速度、准确率保留和 FLOPs 是不同基准/模型/硬件设置的作者结果，不能横向排名；与 RBM 方向无关的旧评价不作为新选题依据。
